# Auto-Wiki: переход от chat-memory к LLM-managed энциклопедии

Расширяем существующий chat-memory до полноценной автогенерируемой вики по паттерну Карпатого. Инфраструктура та же: те же логи, тот же редактор, тот же cron. Меняется политика записи в `wiki/` и появляется индексация по всему сейфу.

## Контекст

- Сейчас: `chat-memory/logs/` пишутся хуком, `chat-memory/logs/summaries/` — крон-задачей. `chat-memory/notes/` уже используется скилами (`capture`, `recall`, `obsidian`), но как картотека, а не как вики — без активных кросс-ссылок и без сводных entity-страниц.
- Цель: превратить `notes/` (после переименования — `wiki/`) в LLM-managed вики, где есть entity/concept-страницы с фактами, источниками и взаимными ссылками. Главный обсидиановский сейф (`~/obsidian-vaul/` минус наша поддиректория) остаётся read-only контуром, мы туда только дописываем `index.md` для навигации.
- Источник идеи: пост Карпатого https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f
- Multi-vault не делаем: `chat-memory` уже LLM-managed сейф де-факто, второй не нужен — обсуждение от 2026-04-26.

## 1. Переименования

Делаем до индексации, чтобы новые `index.md` уже использовали финальные пути.

- [x] 1.1. `~/obsidian-vaul/chat-memory/` → `~/obsidian-vaul/Auto-Wiki/`
  - остановить бота через watchdog или `tmux kill-session -t ginarr`
  - `mv ~/obsidian-vaul/chat-memory ~/obsidian-vaul/Auto-Wiki`
  - `.claude/.env`: `GINARR_VAULT_ROOT=~/obsidian-vaul/Auto-Wiki`
  - дефолт в `.claude/scripts/summarize-day.sh`
  - `.claude/.env.example`
  - правка docs: `docs/architecture.md`, `docs/configuration.md`, все `docs/scripts/*.md`, все `docs/skills/*.md` где упоминается `chat-memory`, `CLAUDE.md`
  - проверка: бот стартует, `log_event` пишет в `Auto-Wiki/logs/`, `summarize-day` находит логи
- [x] 1.2. `Auto-Wiki/notes/` → `Auto-Wiki/wiki/`
  - `mv ~/obsidian-vaul/Auto-Wiki/notes ~/obsidian-vaul/Auto-Wiki/wiki` — структура внутри (`decisions/`, `feedback/`, `projects/`, `reference/`, `user/`, `archive/`) сохраняется
  - найти все скилы, которые пишут в `notes/`: `grep -r notes/ .claude/skills/`
  - обновить `capture`, `recall`, `obsidian`, `obsidian-structure` и любой другой скил, упоминающий `notes/`
  - правка `CLAUDE.md` (раздел Directory layout) и docs
  - проверка: `/capture` работает, `/recall` находит существующие страницы

## 2. Skill: `lint-indexes`

Универсальный обходчик дерева, который чинит `index.md` в каждой папке. Не правит контент, только индекс.

- [x] 2.1. Спек `.claude/skills/lint-indexes/SKILL.md`
  - вход: путь к корню (по умолчанию `$GINARR_VAULT_ROOT`)
  - для каждой папки: если `index.md` нет — создать; если есть — сверить список файлов и подпапок
  - формат строки: `- [<имя>](<file.md>) — <первый H1 или пустая строка>`
  - не удалять и не переписывать существующее содержимое `index.md`, только дописывать недостающее
  - не трогать никакие файлы кроме `index.md`
- [x] 2.2. Прогон по `~/obsidian-vaul/Auto-Wiki/` — наша территория
- [ ] 2.3. Dry-run режим в самом `lint-indexes` для основного сейфа: показывает diff (что бы добавил), без `--apply` ничего не пишет. На основной сейф ходим **только** в этом режиме. Зачем: индексы по всему сейфу нужны для улучшенного grep-поиска, но право на запись в чужую территорию даём только под явный `--apply`.
- [x] 2.4. docs: `docs/skills/lint-indexes.md`, обновить `docs/skills/index.md`

## 3. Skill: `ingest-and-weave`

Главный новый кусок. Находит сущности (люди, места, проекты, технологии) в недавнем разговоре и обновляет соответствующие entity-страницы в `wiki/`.

- [ ] 3.1. Спек `.claude/skills/ingest-and-weave/SKILL.md`
  - **Структура `wiki/entities/`**: одна страница на сущность, snake_case slug, ссылки между страницами через `[[wiki-link]]` (Obsidian-стиль)
  - **Что пишется на странице**: краткое описание + список фактов с датами и обратными ссылками на источник (`[[2026-04-26]]` или путь к JSONL)
  - **Триггер**: ручной (`/ingest-and-weave`) с возможностью указать диапазон дней; на хук `Stop` пока не вешаем
  - **Идемпотентность**: если факт уже зафиксирован — не дублировать, при противоречии — добавить запись «противоречие: <старое> vs <новое>, дата»
  - **Источники**: читать `logs/summaries/` сначала (дешевле), при необходимости докрутить до самих JSONL
- [ ] 3.2. Триггеры: cron как автодефолт + ручной как escape hatch
  - **Авто**: крон-строка в 00:15, цепочкой после `summarize-day`. Читает summary за предыдущий день (не raw JSONL), за каждую сущность из секций `## People` / `## Decisions` / `## Files and paths` дописывает строку на её entity-странице со ссылкой на дату.
  - **Ручной**: `/ingest-and-weave [<date>|now|<entity>]` для срочных обновлений, для бекфилла, для пересборки конкретной сущности.
  - Лаг автодефолта 24h — закрывается ручным режимом.
- [ ] 3.3. docs: `docs/skills/ingest-and-weave.md`, обновить `docs/skills/index.md`
- [ ] 3.4. Миграция существующих `notes/decisions/`, `notes/feedback/`, `notes/user/` в `wiki/entities/`
  - выполняется после стабилизации формата entity-страниц (3.1)
  - для каждого файла в типовых папках: распарсить факт, найти/создать entity-страницу, дописать факт со ссылкой на источник
  - старые папки переехать в `wiki/archive/migration-<дата>/`, не удалять — для возможности сверки
  - переписать скил `capture`: писать напрямую на entity-страницу с тегом типа (decisions / feedback / user) через секцию или frontmatter, не плодить параллельных папок по типу
  - обновить docs `capture` и `recall` (если ходит по старым папкам)
  - тематические агрегаторы (например, `wiki/topics/feedback-colleagues.md`) — допустимы как агрегаторы со ссылками на entity-страницы, не как обязательная структура

## 4. Skill: `lint-wiki`

Здоровье вики: противоречия, осиротевшие страницы, отсутствующие cross-references.

- [ ] 4.1. Спек: поиск противоречий между entity-страницами, orphans (страница без входящих ссылок), пробелы в перекрёстных ссылках
- [ ] 4.2. Запуск: ручной `/lint-wiki`. На крон вешается только **напоминалка** раз в неделю («пора прогнать lint-wiki»), сам lint автоматически не запускается.
- [ ] 4.3. Выход: краткий отчёт в чат + запись в `wiki/_health/<date>.md` для истории
- [ ] 4.4. docs: `docs/skills/lint-wiki.md`, обновить `docs/skills/index.md`

## 5. Skill: `cross-link`

Анализ основного сейфа (`~/obsidian-vaul/` минус Auto-Wiki) и предложение `[[...]]`-ссылок на существующие entity-страницы — как в `Auto-Wiki/wiki/`, так и внутри самого основного сейфа. Цель: улучшить связанность и навигацию по личным заметкам, не подменяя их. **Только ручной запуск, дефолт — dry-run.**

- [ ] 5.1. Спек `.claude/skills/cross-link/SKILL.md`
  - вход: `/cross-link <file|dir>`
  - читает целевой файл, ищет фразы, совпадающие с существующими entity-slug'ами (или их алиасами в frontmatter entity-страницы)
  - дефолт — dry-run: показывает предлагаемые вставки `[[...]]` без записи в файл
  - `--apply` — применяет правки
  - никогда не создаёт ссылку на несуществующую страницу (нужен актуальный список сущностей; синергия с `ingest-and-weave`)
- [ ] 5.2. Запуск: только ручной. Cron не нужен — это интрузивная операция в зону, где ты пишешь сам.
- [ ] 5.3. docs: `docs/skills/cross-link.md`, обновить `docs/skills/index.md`

## Закрытое

- Multi-vault (`GINARR_VAULT_ROOT` как список) — не нужно. `chat-memory` уже LLM-managed сейф; второй обсидиановский контур избыточен.
- `notes/wiki/` (вложенный путь под `notes/`) — не нужно. `notes/` сама становится `wiki/`.
- `notes/journal/` (отдельная папка под человеческие заметки) — не нужно. Эту роль выполняет основной сейф `~/obsidian-vaul/`.
- 3.2 — `ingest-and-weave`: cron в 00:15 после `summarize-day` как автодефолт + ручной как escape hatch (см. секцию 3.2).
- 2.3 — `lint-indexes` для основного сейфа всегда работает в dry-run, `--apply` явно (см. 2.3). Нужно для будущего поискового индекса по сейфу.
- 4.2 — `lint-wiki` ручной, на крон только напоминалка (см. 4.2).
- Capture / type-folders vs entity-pages — переходим на вики-подход. Entity-страницы (`wiki/entities/`, одна на сущность) — основной слой и источник правды. Тематические файлы (`wiki/topics/...`) допустимы как агрегаторы со ссылками на entity-страницы, но не как место хранения фактов. Миграция существующих `notes/{decisions,feedback,user}/` в entity-страницы — пункт 3.4.
